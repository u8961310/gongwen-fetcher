# 國尊公文附件自動歸檔器 — 設計文件

- 日期：2026-05-30（Asia/Taipei）
- 狀態：設計已與使用者確認，待寫實作計畫

## 目標

自動登入國尊公文系統，把「收件夾」裡尚未處理過的公文附件下載下來，依
`簽呈編號_簽呈主旨` 建立本機資料夾並歸位。支援手動觸發與排程定時執行，且為增量
處理（只抓新件，不重複下載）。

## 限制與前提

- 存取方式：純網頁，帳號密碼登入即可（無 CAPTCHA、無自然人憑證、無 OTP）→ 可全自動
- 來源邏輯：預設來源為「收件夾」；系統的「進行中」資料夾內公文視為已處理，跳過
- 機密：帳密放 `.env`，絕不寫進程式碼、對話或 git
- 平台：Windows 10，本機執行
- **使用對象：非技術同事**，且會開放給**其他學校**使用（各校有獨立網址）→ 需傻瓜化交付層，
  且網址必須可設定、不可寫死
- **跨校假設與風險**：各校網址不同沒問題，但前提是各校跑**同一套國尊系統、同樣畫面**，
  selector 才能共用。若某校為客製/舊版、畫面不同，`src/selectors.js` 需為該校另調（技術端處理，
  非同事）。開放前應至少拿一間別校系統實測驗證一次。
- **未知數**：國尊系統登入後的 HTML 結構（selector、清單頁、編號/主旨位置、下載行為）
  目前無法得知，必須先做探勘階段實際登入摸出來

## 交付與安裝（非技術使用者，跨校）

送達方式採 **B 一鍵安裝腳本**（檔案小、可線上更新；代價是同事電腦需能連外，且可能被防毒/
防火牆/Proxy 擋，屬已知風險，需於說明中提供排除指引）。

傻瓜化元件（同事全程只雙擊 `.bat`，不碰文字檔、不打指令）：

| 元件 | 做什麼 |
|------|--------|
| `安裝.bat` → `安裝.ps1` | 偵測無 Node 就下載可攜版 Node 解壓到專案內 `runtime\` → `npm ci` → `npx playwright install chromium` → 跳「安裝完成」 |
| `首次設定.bat` → `src/setup.js` | 命令列問答收集 **網址 / 帳號 / 密碼 / 存放資料夾**，自動寫 `.env`；同事不需編輯任何檔 |
| `執行.bat` | 跑一次 `node src/index.js`，視窗停住（`pause`）顯示「✅ 下載 N 件」或「❌ 登入失敗，請檢查帳密/網址」 |
| `設定每日自動.bat` | 背後 `schtasks /Create … /SC DAILY` 註冊每日排程（當前使用者層級，免系統管理員） |

安全注意：同事帳密以純文字存於其電腦 `.env`，`.env.example` 與 README 需加警告；
Windows DPAPI 加密列為後續強化選項（由使用者依資安政策決定是否現在做）。同時提醒確認
單位政策是否允許「程式自動登入公文系統」。

## 技術選型

Node.js + Playwright 獨立腳本。理由：符合使用者現有 Node 生態與 Playwright 使用習慣；
可手動 `node src/index.js`、雙擊 `run.bat`、或掛 Windows 工作排程器定時跑。

## 專案落地

- 位置：`D:\code\repos\gongwen-fetcher`
- 環境變數（`.env`）：
  - `GW_BASE_URL` — 國尊系統網址
  - `GW_ACCOUNT` — 登入帳號
  - `GW_PASSWORD` — 登入密碼
  - `GW_OUTPUT_DIR` — 本機固定輸出根目錄
- `.gitignore` 必含 `.env`、`node_modules/`、`processed.json`、下載暫存

## 模組切分（每個單一職責）

| 模組 | 職責 | 依賴 |
|------|------|------|
| `config` | 讀 `.env` + 常數（逾時、重試次數、輸出根目錄） | dotenv |
| `login` | Playwright 開瀏覽器、填帳密、送出、確認登入成功 | playwright |
| `listScraper` | 進「收件夾」清單頁，抓出每筆 { 簽呈編號, 主旨, 開啟連結 } | playwright |
| `stateStore` | 讀寫 `processed.json`（已抓過的簽呈編號集合），過濾出新件 | fs |
| `docHandler` | 開單一公文 → 補抓編號/主旨 → 下載附件，回傳本機暫存檔路徑清單 | playwright |
| `fileManager` | 清洗檔名 → 建 `簽呈編號_主旨` 資料夾 → 把附件歸位 | fs |
| `index`（orchestrator） | 串起流程、log、錯誤處理、`--dry-run` 旗標 | 以上全部 |

每個模組可獨立理解與測試：純函式（`fileManager` 的檔名清洗、`stateStore` 的 diff）
不碰瀏覽器，可寫單元測試；瀏覽器模組靠探勘 + dry-run 對真實站台驗證。

## 資料流

```
登入 (login)
  → 抓收件夾清單 (listScraper)
  → 比對 processed.json 取出新件 (stateStore)
  → 逐件：
      開公文 (docHandler)
      抓簽呈編號 + 主旨
      下載附件 → 暫存
      建 `簽呈編號_主旨` 資料夾並歸位 (fileManager)
      成功才標記已處理 (stateStore)
  → 寫回 processed.json
```

## 增量邏輯

- 來源 = 收件夾清單。
- `processed.json` 記錄已成功下載的簽呈編號集合；同一件若仍停在收件夾，跨次執行不重抓。
- 「進行中」資料夾不列為來源（視為已處理）。
- 只有「該件附件全部下載並歸位成功」才寫入 processed.json，失敗的件保持未標記，下次重試。

## 資料夾命名

- 格式：`{簽呈編號}_{簽呈主旨}`（分隔符為底線）
- 例：`1130012345_關於資訊設備採購案`
- Windows 非法字元清洗：`\ / : * ? " < > |` 與結尾空白／句點 → 換成 `_`
- 主旨過長截斷（保留合理長度，避免路徑超長 260 字元限制）
- 同一公文的多個附件全部丟進同一資料夾

## 錯誤處理

| 情境 | 處理 |
|------|------|
| 登入失敗 | 立即中止 + 明確訊息（帳密錯 / 頁面結構變動） |
| 單一公文處理失敗 | log 後跳過、**不**標記已處理（下次自動重試），不影響其他件 |
| 下載逾時 | 重試一次，仍失敗則該件跳過 |
| 資料夾已存在 | 視為已處理，跳過 |
| 多個附件 | 全部歸入同一資料夾 |

## 探勘階段（寫正式邏輯前必做）

用 Playwright 開**有頭瀏覽器**，由使用者在場用真帳號登入一次，實際走過流程把以下摸清楚並
記到 `docs/selectors.md`：

1. 登入表單欄位 selector（帳號 / 密碼 / 送出鈕）與登入成功的判斷依據
2. 「收件夾」清單頁網址與每列結構（簽呈編號、主旨是否在 list 直接可見，還是要進公文才有）
3. 開啟單一公文的方式（連結 / 點列 / 新分頁）
4. 附件下載鈕位置與下載行為（觸發瀏覽器下載？檔案落在哪？是否單檔 / 多檔）

→ 摸清楚後才寫死 selector，再進入實作。

## 測試策略

- 純函式單元測試：檔名清洗（含 CJK 與非法字元）、stateStore diff 邏輯
- `--dry-run` 旗標：登入 + 抓清單 + 列出「會下載哪些、會建哪些資料夾」，但不真的下載 / 建檔
- 瀏覽器流程：探勘階段 + dry-run 對真實站台驗證

## 觸發方式

- 手動：`node src/index.js`，或雙擊 `run.bat`
- 排程：`run.bat` + Windows 工作排程器（每日或每幾小時），提供設定指令
